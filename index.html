AI Architect · Final project

Governed AI Course Generator

The model proposes. The architecture decides. The editor drives.

An AI system that drafts corporate courses for an enterprise learning platform — built so that nothing reaches a learner because it looked convincing. It reaches them because it was grounded in the organization's own knowledge, permitted by policy, consistent with everything already approved, and signed off by a person.

The documents

Two reviewed · five draft · two planned

Nine documents, written to be read in this order — each stage assumes the one before it. About two hours end to end, and stage 1 stands on its own if that is all the time there is.

1 Start here — what the system is, and one run of it end to end ≈ 30 min
01Specification v2 Start here. The whole system in sixteen sections: three layers of responsibility, the generation gateway, the formal stack, what the architecture guarantees and where its limits are. 02Walkthrough reviewed One course from an empty brief to publication in twenty-four steps: every state change, every check, every human stop, and what still reaches the course after it is live.
2 The machine — the states, every legal move, and what blocks the rest ≈ 45 min
03State model draft The two-level state machine: 21 revision states and 11 node states, the event catalog, guards, temporal invariants, and nine situations the machine actually meets. 04Transitions & guards draft Every legal move in both machines — state, event, guard, layer, next state — with all thirty-four guards written out, four legal event chains, twelve forbidden ones, and the moves that have no transition at all.
3 The rules it runs under — who answers which question, what it may do, what it reads ≈ 50 min
05Validation layers draft Which engine owns which question — schema, OPA, Z3, Datalog, Prolog, temporal logic — the rules written out in Rego, Python and Prolog, and the artifact each layer hands back when it refuses. 06Generation safety draft Eleven registered actions with risk levels and compensations, the membrane every one passes through, prompt architecture in full, injection defense across four surfaces, the autonomy ladder and the kill switch. 07Configuration reviewed The seven sources the generator reads at runtime — catalogs, access rules, guardrail policy, policy bundle, thresholds, model routing — their owners, their record shapes, and what is deliberately left as code.
4 Not written yet — the two pages that finish the set
08Evaluation & red team planned Test taxonomy, adversarial scenarios, trajectory evaluation, recorded fixtures and the signals worth watching in production.
09Implementation plan planned Build order, scope boundaries, and the demo script shown at the defense — including the failure it deliberately triggers.
